# Clean DDD

A study project focused on applying **Domain-Driven Design (DDD)** and **Clean Architecture** concepts in a TypeScript application.

## 🎯 Project Goal

The main goal of this project is to explore how software can be structured around business rules rather than frameworks or infrastructure.

Instead of focusing only on building features, this project was created as a practical environment to study concepts such as domain modeling, use cases, repositories, dependency inversion, domain events, and separation of responsibilities.

The idea is to understand how these principles can help create applications that are easier to maintain, test, and evolve over time.

## 🛠️ Technologies

The project was built mainly with:

* **TypeScript**
* **Node.js**
* **Vitest**
* **Prisma**
* **PostgreSQL**

The architecture also explores concepts and patterns such as:

* Domain-Driven Design (DDD)
* Clean Architecture
* SOLID principles
* Repository Pattern
* Dependency Inversion
* Domain Events
* Use Cases
* Unit Testing

## 📚 What I Learned

This project helped me understand that software architecture is not only about organizing folders or choosing frameworks. It is mainly about defining clear boundaries and responsibilities inside the application.

Some of the main concepts I practiced were:

* modeling business rules inside the domain;
* separating application logic from infrastructure;
* using dependency inversion to reduce coupling;
* creating repositories as abstractions for data persistence;
* representing application behavior through use cases;
* using domain events to communicate changes between different parts of the system;
* writing unit tests focused on business behavior;
* keeping the core of the application independent from databases and frameworks.

One of the most important lessons from this project was understanding how architectural decisions affect the maintainability of a system.

By keeping business rules independent from infrastructure details, it becomes easier to test, modify, and evolve the application without requiring major changes to its core logic.

## 💡 About this repository

This repository is primarily a **learning and experimentation project**.

Its purpose is not to represent a production-ready application, but to document and practice architectural concepts that can be applied to real-world software development.
